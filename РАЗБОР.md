# Как работает наш сайт (для защиты)

## 1. Из чего состоит
    app.py          весь сервер: база, вход, заметки, корзина
    static/         сайт, который открывает браузер
      index.html    страница входа и регистрации  + script.js
      main.html     страница с заметками          + notes.js
      style.css     оформление
    data/notes.db   база данных SQLite (создаётся сама)

Браузер показывает страницы и скрипты из `static/`. Когда нужны данные,
`script.js` / `notes.js` отправляют запросы на сервер (`fetch('/api/...')`),
а `app.py` читает или меняет базу и отвечает в формате JSON.

## 2. Путь одного действия: «Сохранить заметку»
1. Пользователь жмёт «Сохранить» → срабатывает `noteForm.addEventListener('submit', ...)` в notes.js.
2. JS чистит текст (`sanitize`) и отправляет `POST /api/notes` с заголовком и текстом.
3. Flask находит функцию `create_note()` в app.py (по `@app.post('/api/notes')`).
4. `@login_required` проверяет, что в сессии есть `user_id`. Если нет — ответ 401, и JS отправляет на страницу входа.
5. `validate_note()` проверяет заголовок и текст и ещё раз чистит HTML (`nh3.clean`).
6. `INSERT INTO notes ...` — запись в базу, в неё кладётся `user_id` текущего пользователя.
7. Сервер отвечает JSON, JS закрывает окно и вызывает `loadNotes()` — список перерисовывается.

## 3. База данных (2 таблицы)
- `users`: id, имя, email (уникальный), хеш пароля, дата регистрации.
- `notes`: id, user_id (чья заметка), заголовок, текст, даты создания и изменения, `deleted_at`.

Корзина: заметка не удаляется, а в `deleted_at` записывается время. `NULL` — обычная заметка,
число — лежит в корзине. «Восстановить» снова ставит `NULL`, «Удалить навсегда» делает `DELETE`.
Благодаря `WHERE user_id = ?` в каждом запросе пользователь видит только свои заметки.

## 4. Безопасность (что и зачем)
- **Хеш пароля** (`generate_password_hash`). В базе нет самого пароля, только необратимый хеш.
  При входе `check_password_hash` сравнивает введённый пароль с хешем.
- **Сессия.** После входа `session['user_id']` хранится в cookie, подписанной `SECRET_KEY`;
  подделать её без ключа нельзя. Cookie `HttpOnly` (JS её не читает) и `SameSite=Lax`.
- **SQL-инъекции.** Запросы пишутся с `?` и значениями отдельно, а не склеиваются в строку.
- **XSS.** Текст заметки — это HTML, поэтому его чистят и в браузере (`sanitize`), и на сервере
  (`nh3`): остаются только теги b, i, u, ul, ol, li, br, div, p, span.
- **CSRF.** Запросы, которые что-то меняют, принимаются только как JSON
  (`only_json`). Чужой сайт не может отправить такой запрос из браузера пользователя.
- **Пароль:** минимум 8 символов, заглавная и строчная буквы, цифра, спецсимвол.
  Проверяется и в браузере (`passwordProblem`), и на сервере (`check_password_rules`).
  Серверная проверка главная: браузерную можно обойти.
- **Чужие данные.** Редактировать, удалять и восстанавливать можно только свои заметки.

## 5. Возможные вопросы и короткие ответы
- **Почему Flask?** Мы знаем Python, а Flask маленький: весь сервер в одном файле, видно каждый шаг.
- **Почему SQLite?** Это база в одном файле, встроена в Python (`sqlite3`), не нужно ничего устанавливать.
  Для большого сайта выбрали бы PostgreSQL.
- **Что такое API и JSON?** API — набор адресов сервера (`/api/notes`), к которым обращается JS.
  JSON — текстовый формат обмена данными.
- **Зачем проверять на сервере, если есть проверка в браузере?** Браузерную можно отключить или обойти,
  запрос можно отправить и без нашей страницы.
- **Что такое GET/POST/PUT/DELETE?** Получить / создать / изменить / удалить.
- **Что такое сессия?** Способ «помнить» вошедшего пользователя между запросами.
- **Зачем «мягкое» удаление?** Чтобы можно было восстановить заметку из корзины.
- **Чего ещё нет?** Восстановления пароля по почте, ограничения числа попыток входа,
  автоочистки корзины. Это можно добавить.
